A simplified BPE-style splitter for illustration. Real tokenizers learn around 100,000 merge rules from data, but they behave the same way: common words stay whole, rare words break into pieces, and a leading space (shown as ·) is part of the token.

Why it matters

  • Pricing and limits are counted in tokens. English averages about 4 characters, or ¾ of a word, per token.
  • Each token ID is a row lookup into the embedding table, which turns the number into a vector (Lab 2).
  • Spelling tasks are hard because the model sees str+aw+berry, not ten letters.
  • Other languages and code often need more tokens per word, so they cost more and fill the context window faster.

Lab 3 · Context

Attention: who looks at whom

Attention lets each token pull in information from other tokens. Every token asks a question (its Query), every token advertises what it holds (its Key), and the match score decides how much of each token's content (its Value) gets mixed in.

The recipe

score(i, j) = Qᵢ · Kⱼ / √d  →  weights = softmax(scores)  →  output = Σ weightⱼ · Vⱼ
  • Many heads run in parallel. One may track meaning, another grammar, another just the previous word.

  • Cost grows with the square of length, which is why long context windows are expensive.
Lab 4 · Output

Next-token sampling

The model outputs a score (logit) for every token in its vocabulary. Softmax turns scores into probabilities, then a sampler picks one. Temperature, top-k and top-p decide how adventurous that pick is.

“The cat sat on the …”

Knobs, explained

  • Temperature divides every logit before softmax. Low values sharpen the distribution toward the top pick; high values flatten it.
  • Top-k keeps only the k most likely tokens.
  • Top-p (nucleus) keeps the smallest set of tokens whose probabilities add up to p.
  • Greedy decoding (temperature near 0) is repeatable, good for extraction and code; higher temperature suits brainstorming.
Lab 5 · Fine-tuning

LoRA: train two thin matrices

Full fine-tuning updates every number in a weight matrix W. LoRA freezes W and learns the change as a product of two thin matrices: ΔW = B · A, where B is d×r and A is r×d. The rank r is tiny, so there is far less to train.

Lab 6 · Variants

The LoRA family: QLoRA, DoRA, VeRA (ELoRA)

LoRA spawned a family of variants. Each one squeezes a different cost: memory for the frozen model, accuracy per parameter, or the number of trainable parameters itself.

QLoRA: freeze the base in 4 bits

QLoRA stores the frozen base weights at 4 bits using NormalFloat (NF4) levels, spaced to match the bell-curve shape of real weights. LoRA adapters stay in 16-bit and train as usual; the base is dequantized on the fly for each forward pass. Fine-tuning a big model then fits on one GPU.

DoRA: split size from direction

DoRA (Weight-Decomposed LoRA) writes each weight column as magnitude × direction. It trains the magnitude directly (one number per column) and uses LoRA only to rotate the direction. That mirrors how full fine-tuning tends to change weights and usually closes some of the gap to it at the same rank.

VeRA (first published as ELoRA): share the matrices, train tiny vectors

VeRA keeps one pair of random, frozen matrices A and B shared by every layer. Each layer learns only two scaling vectors: b (length d) and d (length r). The update is ΔW = Λ_b · B · Λ_d · A. Even with a large shared rank, the trainable count is tiny.

d = 4,096. LoRA shown at rank 8. Only one random seed needs saving for A and B, so an adapter file can be a few hundred kilobytes.

                              Lab 93 · How learning works
                              
        
                              Backpropagation: blame flows backwards
                              
        
                              Gradient descent (Lab 13) needs to know how much each weight is to blame for the loss. Backpropagation works it out in two passes: forward to compute the prediction, then backward, multiplying local slopes together with the chain rule. One backward pass gives the gradient for every weight, whether there are 2 or 2 trillion.

                                Lab 94 · Shrinking models
                                
        
                                Quantization: fewer bits, and the outlier problem

The scale is set by the biggest weight in each group, so a single huge outlier forces a coarse grid on everyone else. Smaller groups, or keeping outliers aside in full precision, fix it at a small memory cost.

                                Lab 95 · More classic machine learning
                                
        
                                k-nearest neighbours: ask the neighbours
                                
        
                                The simplest classifier there is: to label a new point, find the k closest training examples and take a vote. There’s no training at all. With k = 1 every noisy example gets its own little island; with k too large the vote drowns out real structure. The same “closest examples” idea powers vector search (Lab 22) and RAG.

                                  Lab 97 · Knowing the limits
                                  
        
                                  Out-of-distribution: confidently wrong
                                  
        
                                  A classifier trained on cats and dogs has only two answers. Show it a car and it still picks one, often with 99% confidence, because confidence measures which side of the line you’re on, not whether the input looks like anything it was trained on. A simple guard: check how far the input is from the training data, and say “I don’t know” when it’s too far.
